# Solvformer

Encoder-decoder Трансформер, обученный с нуля отвечать на текстовые математические задачи: по вопросу
он пишет программу на Python, а ответом служит результат её исполнения. Модель, цикл обучения, подготовка
данных и генерация написаны на чистом PyTorch, без предобученных весов.

В итоговой модели 74.5M параметров. Она верно отвечает на 75.7% вопросов отложенной валидации
и на 78.4% вопросов публичной части теста. На каждый из 1919 вопросов теста она генерирует и выполняет
12 программ-кандидатов, и всё это занимает 140 секунд на одной T4.

```
$ python -m solvformer.solve --ckpt weights/avg.pt "A pack has 12 pencils. Tom buys 3 packs and gives away 7 pencils. How many pencils does he have left?"
def solve() -> int:
    total_pencils = 12 * 3
    pencils_left = total_pencils - 7
    result = pencils_left
    return result

ответ: 29  (так ответили 12 из 12 кандидатов)
```

Это настоящий вывод итоговой модели.

## Результаты

Метрика pass@1: сгенерированная программа выполняется, её ответ сравнивается с эталоном (относительный
и абсолютный допуск 1e-6). Валидация состоит из 2000 уникальных вопросов, которые убраны из обучающих данных
вместе со всеми копиями. У теста открытых ответов нет, его оценивал внешний проверяющий бот на публичной
части из 960 вопросов.

| Модель | Генерация | Валидация | Тест |
|---|---|---|---|
| 6+6 слоёв, 52.4M, 2 эпохи | жадная | 67.25% | 71.25% |
| та же | голосование по 8 программам | 70.00% | 75.00% |
| 9+9 слоёв, 74.5M, 3.3 эпохи, среднее 6 чекпойнтов | голосование по 8 | 73.90% | 76.98% |
| та же, дообучена ещё 7.5 ч | голосование по 8 | 74.70% | 78.02% |
| та же | голосование по 12 | **75.70%** | **78.44%** |

Жадная генерация с итоговыми весами даёт на валидации 71.85%, то есть голосование добавляет 3.85 п.п.
В таблице курсового соревнования, из которого вырос проект, 78.44% это 10-е место из 59.

Что сдвинуло метрику, а что нет:

| Изменение | Эффект на pass@1 валидации |
|---|---|
| Голосование по исполнению, 12 кандидатов, против жадной генерации | +3.85 п.п. |
| Глубина 9+9 против 6+6 при том же бюджете обучения | +2.7 п.п. |
| Ширина d = 640 против d = 512, на 50% больше параметров | +1.2 п.п. |
| Дообучение с 3.3 до примерно 6 эпох | +1.65 п.п. |
| Усреднение последних чекпойнтов | +0.85 п.п. в одном запуске, в пределах шума в двух других |
| SwiGLU вместо GELU | −2.0 п.п. |
| Ансамбль со второй, более слабой моделью | −1.25 п.п. против того же числа кандидатов от лучшей модели |
| Взвешивание голосов по вероятности программы | в пределах шума для слабых весов, от −0.6 до −1.2 п.п. для сильных |
| Дообучение на части данных, похожей на тест | от −0.3 до −0.75 п.п. |
| Адаптивное число кандидатов | на тесте выигрыша нет |

Все запуски, таблицы и тупики описаны в [docs/experiments.md](docs/experiments.md).

## Как это работает

**Нормализация таргета.** Каждая эталонная программа начинается с `def solve() -> int:` и заканчивается
`return result`. Заголовок, концовка, комментарии и вызовы `print` убираются перед обучением и возвращаются
после генерации, от этого таргет короче на треть. Проверка исполнением показала, что `normalize`
и `denormalize` сохраняют ответ у всех рабочих эталонов из выборки.

**Токенизатор.** Byte-level BPE на 16k токенов, общий для вопросов и кода, обучен библиотекой `tokenizers`.
Числа отделяются до BPE, поэтому число даёт один и тот же токен и в вопросе, и в программе, и модель может
его скопировать. Отказ от regex-предразбиения GPT-2 сократил длину кода в токенах на 40%.

**Модель.** Pre-LN encoder-decoder Трансформер: d = 512, 8 голов, 9+9 слоёв, обучаемые позиции,
одна таблица эмбеддингов для входа, выхода и softmax-слоя. Один модуль внимания обслуживает
и self-, и cross-attention.

**Батчи.** Примеры группируются по длине кода, а внутри по длине вопроса, и доля паддинга в батче падает
с 72% до 14%. Батч ограничен числом токенов, а не примеров, поэтому самые длинные программы
не приводят к нехватке памяти GPU. Самая тяжёлая допустимая форма батча проверяется до начала обучения.

**Обучение.** fp16, AdamW, cosine-расписание по времени (запуск аккуратно заканчивается к лимиту сессии),
DDP на двух GPU (в 1.6 раза быстрее одной) и усреднение последних чекпойнтов.

**Генерация.** Батчевая генерация с KV-cache: энкодер работает один раз, ключи и значения cross-attention
считаются один раз, а на каждом шаге обрабатывается только новый токен. В замере на маленькой модели
это в 14 раз быстрее пересчёта всего префикса. Тест проверяет, что обе версии выдают одни и те же токены.

**Голосование.** На вопрос генерируются одна жадная программа и 11 сэмплированных (температура 0.7,
top-p 0.95). Все они выполняются, одинаковые ответы образуют группы, побеждает самая большая.
Программы исполняются на CPU, пока GPU ещё генерирует следующий батч.

## Быстрый старт

```
git clone https://github.com/dsnillisienko/hse-nlp.git solvformer
cd solvformer
pip install -e .
```

В репозитории лежат токенизатор и валидация. Итоговые веса выложены на Hugging Face:
[DanilLis/solvformer](https://huggingface.co/DanilLis/solvformer), файл `avg.pt` (298 МБ).

```
hf download DanilLis/solvformer avg.pt --local-dir weights

python -m solvformer.solve --ckpt weights/avg.pt 'Cindy paid $54 for a sweater after a 10% sales tax. What was the price before the tax?'
python -m solvformer.generate --ckpt weights/avg.pt --split val --out val_pred.jsonl    # жадный pass@1 на валидации
python -m solvformer.vote --ckpt weights/avg.pt --k 12                                  # голосование при K = 1, 2, 4, 8
```

Модель 6+6 жадно отвечает на 2000 вопросов валидации за 20 с на ноутбуке с M3.

Сгенерированные программы выполняются в отдельном интерпретаторе с таймаутом. Это защищает родительский
процесс от падений и зависаний, но песочницей не является. Работает только на Linux и macOS.

## Обучение с нуля

```
python -m solvformer.prepare download --shards 0-59        # 1.6 ГБ parquet с Hugging Face
python -m solvformer.prepare encode                        # нормализация, токенизация, data/enc/*.npz

torchrun --standalone --nproc_per_node 2 -m solvformer.train --out runs/base --shards 0-59 \
    --d_model 512 --heads 8 --n_enc 9 --n_dec 9 --batch 256 --max_tokens 12288 \
    --lr 1e-3 --warmup 1000 --steps 100000 --max_minutes 540 --keep_ckpts 6
python -m solvformer.average --ckpts runs/base/ckpt-*.pt --out runs/base/avg.pt
```

Итоговая модель обучалась 9 часов с нуля и ещё 7.5 часа дообучалась на двух T4. Ноутбуки
в [kaggle/](kaggle/) запускают те же команды на Kaggle; они собираются скриптами `kaggle/build_*.py`.
В [kaggle/executed/](kaggle/executed/) лежат ноутбуки настоящих запусков с выводом.

Отладочный запуск, который помещается на CPU ноутбука:

```
python -m solvformer.train --out runs/debug --shards 0-1 --steps 3000 --d_model 128 --heads 4 \
    --n_enc 2 --n_dec 2 --batch 64 --eval_every 1000 --eval_n 300
```

## Что где лежит

| Путь | Что внутри |
|---|---|
| `solvformer/model.py` | Трансформер и генерация с KV-cache |
| `solvformer/normalize.py` | Перевод программы в короткое тело и обратно |
| `solvformer/tokenizer.py` | Варианты BPE-токенизатора и их замер |
| `solvformer/data.py`, `prepare.py` | Валидация, скачивание и кодирование шардов |
| `solvformer/batches.py` | Батчи из примеров похожей длины с лимитом токенов |

| `solvformer/average.py` | Усреднение чекпойнтов |
| `solvformer/execute.py` | Исполнение программ в отдельном процессе, pass@1 |
| `solvformer/generate.py`, `vote.py`, `solve.py` | Жадная генерация, голосование, командная строка |
| `tests/` | Тесты |
| `kaggle/` | Ноутбуки подготовки данных, обучения и инференса |
| `data/tokenizer.json`, `data/val.jsonl` | Токенизатор и 2000 вопросов валидации |
| `explore.ipynb` | Исследование данных и проверки по ходу работы |

## Тесты

```
pip install -e ".[dev]"
pytest
```

Тесты покрывают то, что хотя бы раз ломалось по ходу разработки: генерация с кэшем против генерации
без кэша, causal-маска и маска паддинга, loss необученной модели, смещения при склейке шардов,
сдвиг таргета в батче, лимит токенов, исполнитель на зависающих и падающих программах, правило голосования.

## Ограничения

- Модель умеет один узкий жанр: короткие текстовые задачи на английском с числовым ответом.
- Оставшиеся ошибки это ошибки рассуждения, а не синтаксиса: 99.9% сгенерированных программ выполняются
  и возвращают число. Голосование не исправляет ошибку, которую модель делает систематически, например
  забытую ½ в формуле площади треугольника.
- Около 4% эталонных программ в обучающих данных сами сломаны.

## Данные

Обучающие данные: [SlavaYus/tinysms_qa_12m](https://huggingface.co/datasets/SlavaYus/tinysms_qa_12m),
11.8M пар «вопрос и решение на Python» в стиле TinyGSM. Проект начался как курсовое соревнование,
отсюда ограничения: обучение с нуля, encoder-decoder Трансформер, ответы на тест не дольше 180 секунд
на одной T4.
